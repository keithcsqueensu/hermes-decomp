# 02 — The IR: a per-function CFG of JS-shaped nodes

> **Ownership.** *Owns* the intermediate representation itself — the `Expression`,
> `Statement` and `CFG` types — plus how bytecode instructions are lowered into it and how it
> is traversed. *Delegates* the analyses that read the IR to [`03_ANALYSIS.md`](03_ANALYSIS.md),
> the passes that rewrite it to [`04_TRANSFORMS_CODEGEN.md`](04_TRANSFORMS_CODEGEN.md), and
> the instruction *decode* that feeds it to [`01_READ_LAYER.md`](01_READ_LAYER.md).

Files: `ir/` — `builder/`, `cfg/`, `expr/`, `stmt/`, plus `types.rs`, `visitor.rs`,
`depth.rs`, `utils.rs`.

---

## What it does

The IR is the middle tier. It consumes decoded Hermes bytecode — a register machine, one
function at a time — and produces a **control-flow graph of basic blocks whose
statements/expressions are JS-shaped**. It is deliberately *bytecode-faithful and not yet
structured*: registers survive as first-class `Value::Register` operands, and gotos/branches
survive as block terminators. Downstream structure-recovery and codegen (guides 03–04)
rewrite this CFG into structured statements and render JS. The `Display` impls here are for
disassembly/debug output, not the final source emit.

## Core data model

| Type | Where | Role |
|---|---|---|
| `Expression` | `expr/mod.rs` | JS expression tree: Binary, Unary, Call, New, Member, Object, Array, Function, Yield, Await, JSXElement, and an `Unknown{opcode,operands}` escape hatch. Boxed children. |
| `PropertyKey` / `ObjectProperty` | `expr/mod.rs` | member/property key forms (Ident, Computed, String, Index) |
| `BinaryOp` / `UnaryOp` | `expr/ops.rs` | operator enums; rendered by `expr/display.rs` (depth-guarded) |
| `Value` | `types.rs` | leaf operand: `Register(u32)`, `Variable`, `Constant`, `This`, `Global`, `Parameter`, `ClosureVar{level,slot}`, `Arguments`, `NewTarget`, `Super` |
| `Constant` | `types.rs` | the literal enum |
| `BlockId(u32)` / `FunctionId(u32)` | `types.rs` | newtype ids |
| `Statement` | `stmt/mod.rs` | spans both **unstructured** (`Goto`, `CondGoto`, `Expr`, `Assign`) and **structured** (`If`, `While`, `For`, `Switch`, `TryCatch`, `Class`) forms — the latter filled by later passes |
| `AssignTarget` / `Terminator` | `stmt/mod.rs` | lvalue forms (incl. destructuring, `ClosureVar`); block exit (Jump/Branch/Return/Throw/Switch/None) with `successors()` |
| `BasicBlock` / `CFG` | `cfg/mod.rs` | `{id, statements, terminator}`; the function container: `entry`, `BTreeMap<BlockId,BasicBlock>`, `exception_handlers`, `offset_to_block` |

## IR construction (`builder/`)

Entry point: `builder/ir_builder.rs:IRBuilder::build_function(function_id)` →
`build_from_instructions`. It decodes instructions, finds block boundaries, then walks
instructions linearly, dispatching each via `builder/dispatch.rs:dispatch_instruction`,
which routes by opcode **name** through category handler groups
(`opcodes_{load,arith,prop,call,obj,flow,environment,generator,switch}.rs`). Handlers return
a `builder/opcodes_flow.rs:FlowResult` (Statement / Jump / Branch / Return / Throw / Switch /
Noop); the builder appends statements to the current block or terminates it and opens the
next.

**Registers are modeled as-is** — `Value::Register(u32)`, no SSA or naming here (that is a
later pass). The exception is environment/closure slots: `builder/env_state.rs:EnvRegMap`
tracks which nesting *level* each env register holds (from
`CreateEnvironment`/`GetEnvironment`, propagated through `Mov`) so
Load/StoreToEnvironment lower to `ClosureVar{level, slot}`.

## CFG

Block starts are computed by `builder/jump_analysis.rs:find_block_starts_with_handlers`: the
first instruction, every jump target, the fall-through after conditional jumps and after
block-ending ops (Ret/Throw/Jmp), plus exception-handler targets. Blocks are created up
front keyed by bytecode offset (`offset_to_block`); `get_or_create_block` lazily adds any
missed target. Edges are implicit in each block's `Terminator` (`successors()`);
`CFG::predecessors` scans blocks.

**No dominator computation lives here** — traversal is `postorder`/`reverse_postorder`
(recursive DFS from `entry`, additionally seeded from each catch block, since exception edges
are not normal successors, so live-range/SSA passes reach catch bodies). Dominators are
computed where needed by the loop analysis (guide 03, `analysis/loops.rs`). `cfg/dot.rs`
emits Graphviz. `builder/generator_cfg.rs:transform_generator_cfg` post-processes generator
functions, rewriting SaveGenerator+Ret yield-points into `Yield` assignments + jumps.

## Traversal & the depth guard

`visitor.rs` supplies two traits: `Visitor<'a>` (shared) and `MutVisitor` (mutable, used by
transform passes) — both default-method `visit_*`/`walk_*` pairs over every
Statement/Expression/AssignTarget arm, so a pass overrides only the nodes it cares about.

`depth.rs` is a thread-local RAII recursion bound: `DepthGuard::enter()` returns `None` past
`MAX_RENDER_DEPTH` (512). It exists because register propagation can build arbitrarily deep
expression trees, and the recursive `Display` walkers **abort the process** (uncatchable
stack overflow) around ~5000 levels — measured max in a real bundle is 79. Renderers emit
`TOO_DEEP` (a JS comment) instead of descending: degrade loudly rather than crash the whole
decompile (or an MCP session). The budget is thread-local because decompile fans out over
Rayon.

## Notable design decisions / gotchas

- **Two-stage IR.** Blocks are *flat* at build time; a handler emitting multiple statements
  returns them as `Statement::Block`, which the builder flattens inline. Structured
  statements exist in the enum but are populated by later `MutVisitor` passes.
- **Recursion is the pervasive risk.** Every walker (Display, visitor,
  `utils::expr_uses_register`, `has_side_effects`) recurses over boxed trees. The depth guard
  only protects *rendering* — even *dropping* a deep `Box<Expression>` chain is recursive and
  can overflow, mitigated only by the large worker stacks (`configure_thread_pool`).
- **`EnvRegMap` is flow-insensitive** ("last-write" per register), with unknown env
  registers conservatively defaulting to level 0 — a deliberate approximation.
- **Unknown opcodes never fail** — they become `Expression::Unknown` / `Statement::Comment`,
  keeping the decompile total.
- Empty functions synthesize a `Return(None)`; a fall-off-the-end block gets
  `Return(undefined)`.
