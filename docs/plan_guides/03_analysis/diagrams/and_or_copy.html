The a && b || c copy

Commit 48e2794 keeps the middle test when the arms return. A later change keeps it when the arms assign a value used later too. Harder shapes such as (a && b || c) && d are still wrong. The cases below are real hermes-decomp output on v98 bytecode, compared with the Hermes VM.

Why the test was lost

Hermes compiles the condition to three tests. Structure recovery follows the false arm of a first, which places c, else and then. When it finally reaches b, nothing is left to place.

What the copy does, and when it refuses

A structured program cannot jump to a block that is already placed, so the fix prints c a second time inside the arm of b. It first has to know the copy's values do not leave the copy.

Fixed: the arms return

if (a && b || c) return "then"; return "else"; The tail assigns nothing that is read later, so the copy goes through. t(1, 0, 0) is the call that separates them: the VM returns "else".

Before: b is gone, returns "then" 
const tmp = arg0;
if (!tmp) {
  const tmp3 = arg2;
  if (!tmp3) {
    return "else";
  }
}
return "then";
After: b kept, c copied, returns "else" 
const tmp = arg0;
if (!tmp) {
  const tmp3 = arg2;
  if (!tmp3) {
    return "else";
  }
} else {
  const tmp2 = arg1;
  if (!tmp2) {
    const tmp4 = arg2;
    if (!tmp4) {
      return "else";
    }
  }
}
return "then";

Fixed later: the arms assign

let r; if (a && b || c) r = "then"; else r = "else"; return r; Register r0 is assigned in the tail and read by the return past it. 48e2794 refused this copy and printed the code below, where t(1, 0, 0) returns "then". Sharing r0 now tests arg1 and returns "else", as the VM does.

let str;
const tmp = arg0;
if (!tmp) {
  str = "then";
  if (!arg2) {
    str = "else";
  }
} else {
  str = "then";   // arg1 is never tested
}
return str;
