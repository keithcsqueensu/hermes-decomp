Several ways out

The lifter refuses a try whose region has more than one exit, because it cannot tell which exit is the code after the try. A return inside the try looked like a second exit.

The example is g1 from the corpus test gen_return_in_try, on v98:

function* g1(x) { try { if (x) return 1; yield 2; } catch (e) { yield 3; } yield 4; return 5; }

The boundary moves past the return

The old check accepted only an empty block ending in a return. The generator's state store leaves r = 3 in that block, so it never matched.

Why a real call in the return is still safe

In return f(x), the call runs before the exit, while the try is still active. Only the return of its result moves. If f throws, the catch still runs: the test's g2(2) returns 7 in the VM and in the decompiled code.

A shared return block can also have predecessors outside the region. Those blocks are left out of the check for a second way in, otherwise a shared return would turn this refusal into a “two ways in” refusal.

This fix only widens what counts as a harmless exit. A try with two exits that can really throw is still refused and stays raw, and that is the safe result.
